# Changelog

## Unreleased

- **Omni search `requiredCriterion`**: `findAsValueMapOmni`, `findAsValueMapOmniStream` and `countOmni` take a new last parameter `requiredCriterion: Criterion = NoCriterion`, criteria every returned (or counted) doc must match, kNN hits included; it doesn't affect the score (ES filter clause). The existing `criterion` remains an optional score boost (ES should clause): docs matching it are added to the full-text matches and ranked higher, so it widens rather than narrows the results; the Scaladoc now says so. E.g. searching a text within a library needs `requiredCriterion = "library" #== "x"`. Internally the bool query sets `minimum_should_match = 1` (ES drops it to 0 once there's a filter clause), and the required criterion is also passed to the kNN section, which ES applies apart from `query`. A doc matching the required criterion and `criterion` but not the full-text query is still returned, as before. Source-compatible; dependants must recompile.

## 1.2.0 (2026-10-16)

- **Scripting isolation fix (security)**: pooled GraalVM contexts leaked data between callers. Injected JSON inputs (`<name>_string_<n>` bindings) and the parsed variables stayed in Python `globals()` and piled up; a reset bug left user globals and its own loop variables behind; builtins, pre-imported modules and JavaScript prototypes/built-ins were never restored; and the JavaScript reset deleted `globalThis`, `Reflect` and `Intl` after a context's first use. After every eval the pool now always removes the injected bindings and restores the context to a snapshot taken right after warmup, through a restore function held only on the host side. A context whose cleanup fails is replaced; if no replacement can be created it is quarantined and never serves another eval dirty. JavaScript no longer re-runs a failing script at top level on the error path.
- **Isolated script evaluation**: `evalToString` / `evalToJson(code, bindings, isolated = true)` run a script in a fresh context that is created for the call and closed afterwards; `GraalPoolConfig(freshContextPerUse = true)` or `graalvm.<js|python>.fresh_context_per_use = true` does the same for a whole pool. Pooled mode stops accidental carry-over but is documented as not being a security boundary; use isolated mode for untrusted scripts. Source-compatible for callers; `GraalPoolConfig` gained a field and `GraalScriptPool` two methods, so dependants must recompile.
- **Apache Spark 3.5.6 → 4.0.4**: officially supported on JDK 17 and 21 (Spark 3.5 stops at 17). Brings **Scala 2.13.11 → 2.13.16** (the version Spark 4.0 is built with) and **Jackson 2.14.3 → 2.18.6** suite-wide (Spark 4.0 needs 2.18; Spark, Play, Akka and elastic4s share one classpath). Netty stays on 4.1, which is why 4.0.x was chosen over 4.1/4.2 (Netty 4.2, Jackson 2.21). Code changes: `ForwardChainingCrossValidator` persistence takes the `SparkSession`, and `sqlContext.implicits` imports became `session.implicits`. Spark 4 turns ANSI SQL mode on by default; `SparkAppImpl` and `SparkMLApp` set `spark.sql.ansi.enabled = false` to keep the 3.x semantics (override with `spark.sql.ansi.enabled` in the config). Processes running Spark still need Spark's `--add-opens` JVM options (as with 3.5); Spark 4's launcher also adds `--add-modules=jdk.incubator.vector` and `-Dio.netty.tryReflectionSetAccessible=true`, which are recommended but were not required in testing.
- **Guice 5.1.0 → 6.0.0** (with guice-assistedinject and scala-guice 6.0.0) in every module; `ada-web` already ran Guice 6.0.0 through Play and play-mailer, now matched by scala-guice. Guice 5.1.0's bundled ASM 9.2 cannot read Java 21 class files, so on JDK 21 a binding error involving such a class surfaced as `Unsupported class file major version 65` instead of the real message. Not 7.x, which supports only `jakarta.inject` (Play 2.9 uses `javax.inject`).
- **New `Text` field type (full-text search)**: free-form strings that are searched by words. Values are plain strings as for `String`; in Elasticsearch a Text field is a `keyword` (exact values up to 256 chars, `elastic.text.keyword_ignore_above`) plus an analyzed sub-field `<field>.text` (analyzer `elastic.text.analyzer`, default `standard`); Mongo and the cache store it unchanged.
  - **Inference**: a string field whose longest value has at least 50 characters is inferred as Text (after Enum, before String). Configurable per import (`inferenceMinTextLength` for CSV, JSON, tranSMART) and for the infer transformation (`minTextLength`).
  - **Conversion**: String fields can be turned into Text (and back) in place, without copying data: the dictionary "Text Type"/"String Type" actions on selected fields, a type change in the field edit form, `DataSetService.convertStringAndTextFields`, or the `ConvertStringAndTextFields` runnable. For Elasticsearch the sub-field is added to the mapping and populated by an update-by-query (re-runnable, e.g. to finish an interrupted one). A failed conversion restores the original field types and reports its cause; only one conversion per data set runs at a time.
  - **`contains` filter condition** (`ContainsWordsCriterion`): all the given words must occur, case-insensitively. On Elasticsearch Text fields whole words are matched through the full-text sub-field; elsewhere substrings (Elasticsearch String fields: a case-insensitive regexp `.*<word>.*` per word, taken literally; Mongo and cache: equivalent regex/LIKE). The filter pre-selects `contains` for Text fields.
  - Text fields are left out of the categorical/numeric widget, correlation and ML field pickers; they are exported, rendered (incl. URLs), and replaced like Strings.
- **Fix: Mongo `not like` now negates `like`**: it matched values that don't *start* with the regex (`^(?!value)`), while `like` matches it anywhere; now it matches values in which the regex occurs nowhere. Saved filters using `not like` on Mongo data sets return fewer items (those containing the value elsewhere are now excluded).
- **Synapse re-imports map new fields before saving**: a re-import upserts into the existing Elasticsearch index (no re-creation), so new columns were mapped dynamically by Elasticsearch, e.g. a new Text column as plain `text` without its full-text sub-field (so `contains` found nothing). New fields are now put into the mapping first (best-effort: a rejected mapping only logs a warning).
- **Fix: a failed data set store re-creation no longer blocks later ones**: the store-update lock was released only on success, so after one failure (e.g. Elasticsearch unreachable) every later import or store refresh of that data set hung until restart.
- **Elasticsearch String fields**: `ignore_above` lowered from 30000 to 8191 chars for new indices, since Lucene's term limit is 32766 bytes and longer non-ASCII values made whole documents fail to index.
- **Java sources compile with `--release 17`** (build-wide `javacOptions`), so the published jars keep Java 17 bytecode whichever JDK builds them. Scala output is unchanged (Java 8 bytecode).

## 1.1.1 (2026-09-09)

- **Apache Spark 3.5.4 → 3.5.6**: patch release with CVE fixes; Spark 4.0 deferred because of its breaking changes.
- **ScalaTest 3.0.8 → 3.2.19** and **ScalaTestPlus Play 4.0.3 → 6.0.2** (Play 2.9.x line): all test suites migrated to the 3.1+ style-trait packages (`org.scalatest.flatspec.*`, `org.scalatest.funsuite.*`, `org.scalatest.matchers.should.Matchers`); the `kafka` module now uses the shared ScalaTest version instead of its own pin.
- **Reflections 0.9.10 → 0.10.2** (`ada-server`): the class finder builds its scanner from an explicit classpath configuration, since the no-arg constructor became protected; the old findbugs exclusion is no longer needed.

## 1.1.0 (2026-09-09)

- **Platform upgrade**: Play 2.9.6, Akka 2.6.21, Play JSON 2.10, Jackson 2.14, Apache Spark 3.5.4, Apache Ignite 2.14, sbt 1.9.6, PAC4J 12 / OIDC 6.2, Deadbolt 2.9, ReactiveMongo for Play 2.9; dependency pins for known CVEs (Netty, commons-lang3, commons-io, jQuery UI 1.14, D3 v7).
- **Elasticsearch 8.x**: Elastic4s 8.19; kNN (vector) and nested-document search, fuzzy search settings, object-vs-nested mappings, basic auth, and a dynamic read-only store built from an index's live mapping.
- **New `scripting` module**: GraalVM polyglot JavaScript and Python execution with thread-safe "default" and "admin" pools, per-run variable isolation, and lazy context recycling.
- **New `kafka` module**: producer and Akka Streams consumers with Schema Registry serialization and dead-letter-queue support.
- **Secrets**: symmetric (AES-GCM) encryption of `enc:v1:`-prefixed config values and environment variables, master key and optional pepper supplied from files or systemd/Docker secret locations, plus an env-file encoder (CLI, Ada runnable, and web UI).
- **Charts**: four pluggable widget engines — Plotly (default), ApexCharts, ECharts, and Highcharts. Highcharts is proprietary and is no longer bundled; it loads from Highsoft's CDN (or a deployer-supplied webjar) and the data set settings show a licensing notice when it is selected.
- **Exports**: exports stream with a per-export batch size chosen as Low / Medium / High in the export dialogs (sizes configurable under `elastic.scroll.batch.levels`), instead of the global scroll size; shipped global default lowered from 10000 to 1000. JSONL export and JSON/JSONL item import added across CRUD views, with an in-browser JSON item editor.
- **Statistics and UI**: binned box and aggregation widgets, Spearman correlation, date-binned distributions, run-script screens, and refreshed form styling.
- **Build hygiene**: the Barnes-Hut t-SNE implementation is vendored (BSD-3) so the build no longer depends on jitpack; reflection-based JSON format/schema helpers; expanded Elastic mapping and nested-search test suites.
